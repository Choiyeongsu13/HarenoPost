# 03. 기능 명세

각 기능의 URL은 `06_api.md`, 화면 시안은 `07_screens.md` 를 본다. 화면 문구는 일본어로, 아래 메시지 예시를 그대로 쓴다.

## 공통 입력 규칙

Oracle `VARCHAR2(n)` 은 바이트 단위이고 일본어는 UTF-8로 3바이트이므로 **글자 수로 검사**한다.

| 항목 | 규칙 |
|---|---|
| 아이디 | 영문 소문자·숫자 4~20자, 첫 글자 영문 |
| 패스워드 | 8~20자, 영문+숫자 포함 |
| 닉네임 | 1~10자 |
| 이메일 | 형식 검사, 중복 불가 |
| 포스트 이름 | 1~20자 |
| 이름표 | 0~8자 |
| 카드 보낸 이름 | 1~10자 |
| 카드 본문 | 1~300자 |
| 신고 사유 | 1~100자 |

---

## F1. 회원

### F1-1 회원가입 (`/signup`)
1. 아이디 입력 후 「重複確認」 → ajax로 중복 확인. 확인 후 아이디를 바꾸면 다시 확인해야 한다.
2. 이메일 입력 후 「認証コード送信」 → 서버가 6자리 코드를 만들어 **세션**에 `{email, code, 만료시각(5분)}` 으로 저장하고 메일 발송. 코드는 응답에 넣지 않는다.
3. 코드 입력 후 「確認」 → 맞으면 세션에 `verifiedEmail` 저장.
4. 「登録する」 → 서버에서 다시 검사: 아이디 중복, 이메일 중복, `세션 verifiedEmail == 입력 이메일`, 입력 규칙. 통과하면 BCrypt로 저장, 세션 인증 정보 삭제, `/login?joined` 로 이동.

| 예외 | 메시지 |
|---|---|
| 아이디 사용 중 | このIDはすでに使われています |
| 중복 확인 안 함 | IDの重複確認をしてください |
| 이메일 사용 중 | このメールアドレスはすでに登録されています |
| 코드 불일치 | 認証コードが正しくありません |
| 코드 만료(5분) | 認証コードの有効期限が切れました。もう一度送信してください |
| 메일 인증 안 함 | メール認証を完了してください |
| 코드 재전송 | 30초 안에 재전송 불가: しばらくしてからもう一度お試しください |

### F1-2 로그인 / 로그아웃
- Security formLogin. 로그인 페이지 `/login`, 처리 URL `/login`(POST), 성공 시 저장된 요청 또는 `/mypage`.
- 실패 시 `/login?error` → 「IDまたはパスワードが正しくありません」
- 성공 시 `last_login` 갱신(SuccessHandler).
- 로그아웃 `/logout`(POST) → `/`.

### F1-3 마이페이지 (`/mypage`)
- 프로필(닉네임, ID, 메일, 생일, 가입일), 만든 포스트 수, 받은 카드 수 합계.
- 내 포스트 목록(최신순): 이름, 테마, 개봉일, 카드 수, 상태(受付中 / 開封済み). 개봉 전 → `/post/{code}`, 개봉 후 → `/post/{code}/cards`.

### F1-4 프로필 수정 / 탈퇴 (`/mypage/edit`)
- 닉네임, 생일 수정. 이메일 변경 시 F1-1의 이메일 인증을 다시 거친다.
- 패스워드 변경: 현재 패스워드 확인 후 변경.
- 탈퇴: 패스워드 확인 → 회원 삭제(포스트·카드·신고 CASCADE) → 로그아웃.

## F2. 포스트

### F2-1 포스트 만들기 (`/post/new`) — 회원
- 화면: 테마 3종(아이콘 버튼), 개봉 날짜·시간, 포스트 이름. 테마를 고르면 미리보기 배경·장식·개봉일이 바뀐다(`theme-art.js`).
- お正月·クリスマス는 날짜 입력이 잠겨 있다. 서버는 **입력값을 무시하고** 직접 계산한다.
- 誕生日: 기본값 = 다음 생일 0:00. 회원이 바꾼 값은 `현재 < openDate ≤ 현재+1년` 이어야 한다.
- 저장: code = `UUID` 에서 `-` 를 뺀 앞 8자(중복이면 다시 생성), decos = 테마의 3개 장식 전부(기본), nameTag = 닉네임 앞 8자.
- 완료 화면: 공유 링크 + 복사 버튼, 「ポストをかざる」「ポストを見る」.

| 예외 | 메시지 |
|---|---|
| 이름 비어 있음 | ポスト名を入力してください |
| 개봉일이 과거 | 開封日は今より後の日時を選んでください |
| 개봉일이 1년 넘음 | 開封日は1年以内で選んでください |
| 受付中 포스트가 이미 5개 | 同時につくれるポストは5つまでです |

### F2-2 포스트 꾸미기 (`/post/{code}/decorate`) — 주인
- 위쪽에 현재 테마, 미리보기(빨간 우체통 + 장식 + 이름표), 장식 3개 체크(여러 개), 이름표 입력.
- 「保存する」 → ajax `PUT /api/posts/{code}/decorate` `{decos:[...], nameTag}`.
- 서버 검사: 주인인지, 개봉 전인지, 모든 장식 코드가 **이 포스트 테마의 장식**인지, 중복 없는지, 이름표 8자 이하.
- DB에는 `decos` 를 슬롯 순서(top, front, side)로 정렬한 CSV로 저장. 빈 목록이면 NULL.

| 예외 | 메시지 |
|---|---|
| 다른 테마 장식 | 選べない飾りが含まれています |
| 이름표 8자 초과 | 名札は8文字までです |
| 개봉 후 | 開封後は変更できません |

### F2-3 포스트 화면 (`/post/{code}`) — 누구나
- 배경, 우체통(장식·이름표), 포스트 이름, 개봉일, 카운트다운(`.countdown[data-open-at]`), 받은 카드 수, 봉투 목록(보낸 이름 + 디자인 썸네일).
- 방문자: 「カードを書く」 버튼(개봉 전에만), 링크 복사.
- 주인: 추가로 「かざる」「設定」 버튼. 개봉 후에는 「カードをひらく」(→ `/post/{code}/cards`).
- 없는 코드 → 404 화면 「ポストが見つかりません」.
- **카드 본문은 이 화면의 모델·HTML에 넣지 않는다.**

### F2-4 포스트 설정 (`/post/{code}/edit`) — 주인, 개봉 전
- 이름, 기념일, 개봉일 변경(규칙은 F2-1과 같음). 기념일을 바꾸면 decos를 새 테마 기본값으로 초기화.
- 삭제: 확인 모달 → `POST /post/{code}/delete` → 카드·신고 CASCADE → `/mypage`.

## F3. 카드

### F3-1 카드 보내기 — 누구나 (포스트 화면의 모달)
- 모달: 카드 디자인 선택(이 테마 전용 + 공통, `use_yn='Y'`, `sort_order` 순), 보낸 이름, 본문(글자 수 표시).
- ajax `POST /api/posts/{code}/cards`. 성공하면 모달을 닫고 봉투를 하나 추가, 카드 수 +1, 토스트 「カードを届けました！」.
- 서버 검사 순서: 포스트 존재 → 개봉 전 → 입력 규칙 → 디자인이 사용 가능하고 테마가 맞거나 공통 → **같은 IP의 마지막 카드가 1분 이내면 거절**.
- IP: `X-Forwarded-For` 첫 값, 없으면 `request.getRemoteAddr()`.
- 로그인한 회원이면 보낸 이름에 닉네임을 미리 채운다(수정 가능). 주인 자신도 보낼 수 있다.

| 예외 | HTTP | 메시지 |
|---|---|---|
| 개봉 후 | 400 | このポストはもう受付を終了しました |
| 1분 이내 재전송 | 429 | 少し時間をおいてから送ってください（1分に1通まで） |
| 본문 비어 있음/300자 초과 | 400 | メッセージは1〜300文字で入力してください |

### F3-2 카드 열어보기 (`/post/{code}/cards`) — 주인, 개봉 후
- 개봉 전 접근 → 포스트 화면으로 redirect + 「まだ開封日ではありません」.
- 주인 아님 → 403.
- 목록: 봉투(안 읽은 카드는 표시). 누르면 모달에 본문 표시, 동시에 ajax `POST /api/cards/{idx}/read`.
- 본문은 이 화면 진입 시 서버 렌더링으로 넣어도 된다(주인·개봉 후가 확인된 뒤이므로).

### F3-3 카드 신고 — 주인, 개봉 후
- 카드 모달의 「通報」 → 사유 입력 → ajax `POST /api/cards/{idx}/report`.
- 같은 카드에 이미 WAIT 신고가 있으면 「すでに通報済みです」.

## F4. 관리자 (`/admin/**`, ROLE_ADMIN)

### F4-1 신고 관리 (`/admin/reports`)
- 상태별(WAIT/DONE) 목록: 신고일, 사유, 카드 본문, 보낸 이름, 포스트 이름.
- 「カード削除」 → 카드 삭제(신고 CASCADE). 「処理済み」 → status DONE.

### F4-2 카드 디자인 관리 (`/admin/designs`)
- 목록(순서, 이름, 테마, 썸네일, 사용 여부).
- 등록: 이름, 테마(SHOGATSU/BIRTHDAY/CHRISTMAS/공통), 이미지(png/jpg/webp, 2MB 이하). `app.upload-dir` 에 `UUID.확장자` 로 저장, `/upload/**` 로 제공.
- 사용 여부·순서 변경. 삭제 시 이 디자인을 쓴 카드는 `design_idx = NULL`(기본 카드 모양으로 표시).
